# 템플릿 인계 등록 후보 생성 (#396)

2026-10-25의 R1/T1/S1 선택 이후 실제 review composition은
[승인 정책 모드](RESET_APPROVED_HANDOVER_POLICY.md)로 현재 게시본의 새 draft status/version을
계획한다. 아래 두 선택과 status/version 미정 설명은 범용 순수 검사 모드의 계약이다.
정책 모드에서 `ALL_VERSIONS`는 거부하며 실제 등록·게시·이력 변경은 실행하지 않는다.

`template-plan-builder.ts`는 검증된 전체 템플릿 목록에서 새 개발자 인계 등록 **후보**를 만든다.
공개 경로·DB·게시·삭제 호출은 없다. 실행은 항상 비활성이고 사용자의 선택을 대신하지 않는다.
기존 `template-reseed-plan.ts`의 내용·provenance 비교를 재사용한다.

서버 입력은 모든 draft/published/retired 템플릿·독립 건수·명시된 전체 참조와
project/source/catalog/snapshot/content 결합이다. 내용 지문은 원본 버전·작성자·시각·상태와
모든 허용 슬롯 속성을 포함하고 ID와 displayOrder로 정규화한다. 이 입력과 완전성 표시는
클라이언트 자기 신고로 받지 않는다. source129의 공개 합계만으로 이 비공개 전체 입력을 만들 수 없다.
원본과 별도로 수집한 예상 binding을 비교하며, 같은 건수의 내용·원 작성자 변경도 거절한다.

선택은 `CURRENT_PUBLISHED` 또는 `ALL_VERSIONS`를 반드시 명시해야 한다. 기본 선택이 없다.
현재 게시본이 같은 객실 타입·청소 종류에 둘 이상이면 임의로 하나를 고르지 않는다.
비선택 버전도 전체 ID 충돌 검사와 내용 결합에 포함한다. 누락/중복/불완전/참조 단절은 부분 계획으로
넘기지 않는다. 최대10,000버전/10,000참조 중 최대1,000개 선택을 지원한다.

선택한 원본에 새 UUID와 서버 clock의 실제 새 시각, developer ID,
`OPERATIONAL_HANDOVER_INITIALIZATION` 사유를 부여한다. 원본 ID·다른 버전 ID·이번 생성 ID의
충돌은 재사용하지 않으며 ID당 최대8번 시도 후 전체 후보를 실패 처리한다. 외부 효과의 재시도가 아니다.
원본 작성자와 과거 작성 시각은 별도 provenance로 유지하고 원자료를 수정하지 않는다.
내용·슬롯 수·표시 설정은 그대로 복사하며 legacy 내용을 현재 게시 형태로 변환하지 않는다.

새 상태·버전 번호·게시 자격·과거 이력 보호 방식은 후보에 임의로 채우지 않는다.
구→신 ID 대응은 등록 내용의 연결만 의미한다. 기존 current pointer와 historical snapshot 참조를
새 ID로 바꾸지 않고 참조가 있으면 `referencesComplete=false`로 남겨 후속 계획을 차단한다.
템플릿이 비어 있어도 실제 DB가 비었다는 독립 증명이나 초기화 승인이 되지 않는다.

반환되는 plan과 originalProvenance는 **서버 내부 전용**이며 공개 API·로그·인계 문서에 원문을
출력하면 안 된다. 실패는 원자료 없이 고정 코드와 null 후보만 반환한다. 원장/버전·상태·전체 참조
처리·실제 백업·권한/재인증·최종 DB 검증이 연결되기 전에는 등록을 실행할 수 없다.
이 모듈은 데이터를 수집하거나 백업하지 않으며 정책과 실행 승인 항목은 USER_DECISIONS에 별도 유지한다.

합성 회귀는 두 명시 선택, 원본 내용/provenance 보존, 배열 순서 정규화, 누락/변경/중복/참조 단절,
비선택 ID 충돌, 제한된 ID 생성, 잘못된 시각, 중간 생성 실패와 빈 목록의 실행 차단을 검증한다.
실제 SQL·등록·게시·복구·초기화는 NOT RUN이다.
