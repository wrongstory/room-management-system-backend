# 관리자 강제 회수와 재배치 (#607)

**개발 후보. 운영 적용 전.** 142호와 같이 청소 업무는 진행 중이고 실제 수행은 현장 완료됐으나 아직 제출되지 않은 경우를 지원한다.

1. 관리자 업무 상세에서 GET `/v1/assignments/{cleaningTargetId}/force-recall`로 회수 가능 여부를 확인한다. 유효한 현재 통보 배정, 현장 완료 시각, 최신 수행 및 제출 이력을 검사한다. 가능하면 `candidate`에 현재 담당/배정 버전과 수행 ID/버전을 반환한다. 불가능하면 null.
2. 관리자가 **강제 회수**를 확인하면 같은 경로에 POST한다. 조회한 candidate 자체를 JSON 본문으로 사용하고 Idempotency-Key를 보낸다. 일반 해제 및 수행 불가 신고와 별도 버튼이다. 409이면 새로 조회하며 같은 입력의 통신 실패에는 같은 키로 재시도한다.
3. 성공 응답의 `reassignTargetId`와 `assignmentVersion`을 사용하여 기존 배정 초안 → 새 메이드 선택 → 통보를 진행한다. 회수 트랜잭션과 다음 배정은 별도다. 이미 지난 업무는 일정 이월·근무 가능일 등 기존 배정 검사를 따른다. 재청소는 원래의 0원 업무 이력을 종료하고 기존 정책에 따라 정상 요금의 대체 업무를 제공한다.

원 수행 회차의 시작·현장 완료·종료 시각, 작성자, 사진·업로드 기록을 보존한다. 회차 상태는 superseded로 남기고 강제 회수 시각·관리자는 별도의 감사 기록에 남긴다. 이전 담당자의 업로드/제출 권한과 오프라인 사용 권한을 회수하며 배정 종료 알림을 기록한다. 후임자는 새 배정 이력과 새 수행 회차를 갖는다. 제출과 같은 잠금 순서를 사용하고 잠금 이후 실제 제출 이력 및 버전을 검사한다. 실제 동시 DB 실행은 최종 릴리스 검증 대상이다.

프런트 연결 및 확인 항목은 [프런트 #321](https://github.com/makee-ham/room-management-system/issues/321)에서 관리한다. DB source153과 격리 SQL 회귀는 작성만 했다. 실제 DB·마이그레이션·운영 적용 전 별도 승인 필요. 롤백 시 이전 API로 복귀하고 이미 기록된 회수나 후임의 수행을 임의로 되돌리지 않는다.
